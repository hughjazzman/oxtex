\section{Introduction}
The task of obtaining the stabiliser decomposition for classical simulation purposes
has only been discussed at a high level so far.
While we have the various methods of magic state, cat state decompositions, 
along with graph cut decompositions,
we have not yet detailed the specific steps taken to obtain the stabiliser decompositions
in the most efficient way known.

In modeling our task, we can think of the stabiliser decomposition almost as a search problem, 
where we are searching for the most efficient stabiliser decomposition.
We can visualize an example as in \autoref{fig:search-tree}, where $V$ is a Clifford+T diagram at the root.
The directed edges represent the decomposition used from the parent to the child node, 
and the leaves $d_i$ are the possible stabiliser decompositions.

\begin{figure}[h!]
\ctikzfig{search-tree}
\caption{Example tree for a stabiliser decomposition}
\label{fig:search-tree}
\end{figure}

One question that arises is how we can efficiently traverse this tree.
It is strongly believed that the stabiliser rank itself must increase exponentially with the $T$-count $t$,
so we cannot have $\chi(V) = 2^{o(t)}$ \cite{Morimae:2019onp}, as cited in \cite{Qassim_2021}.
Thus, even if it was possible to know the most efficient decomposition, at each node,
we would still face the exponential number of terms.
In \autoref{fig:search-tree}, this means that not just that we have an exponential 
number of decompositions to consider, but also that 
every stabiliser decomposition $|d_i| = O(2^{\alpha t})$ would have an exponential number of terms.

\begin{alg}
\label{alg:stabiliser-decomposition}
To traverse the tree, we might take the following steps \cite{Kissinger2022cat,Kissinger_2022}.
\begin{enumerate}    
    \item Perform necessary spider $\SpiderRule$usions to 
    \hyperref[prop:zx-to-graph]{reduce to graph-like form}.
    \item Apply a chosen decomposition ("choose an edge").
    \item Simplify the resulting Clifford+T diagram using \hyperref[alg:zx-simplify]{ZX-simplify}.
    Some Clifford spiders may be removed, and some $T$-like spiders may be combined.
    \item Repeat steps 1-3 until the $T$-count is 0.
\end{enumerate}
\end{alg}

The complexity from using this algorithm was found to be $O(N^3 + 2^{\alpha t}t^2)$, 
where $N$ is the number of gates in the original circuit \cite{Kissinger_2022}.
Clearly, any circuit with a $T$-count $t$ that is not insignificant will mean that 
the complexity is dominated by $O(2^{\alpha t}t^2)$.

In this thesis, we will focus on the second step of the algorithm, 
where we choose the decomposition to apply at each node.
There are a variety of ways to choose a decomposition, detailed in the next few sections.



\section{Greedy Algorithm}

The most obvious way to obtain an efficient decomposition is to, at each step, use the decomposition 
that has the smallest associated value of $\alpha$ as possible.
This is essentially a greedy algorithm, and is the method used in \cite{Kissinger2022cat,Kissinger_2022}.
Intuitively, this should give us a decomposition with an $\alpha$ upper bounded by 
the worst decomposition available.
More formally, we have the following lemma.

\begin{lemma}
    Let $d$ be a stabiliser decomposition, 
    and let $\alpha_1,...,\alpha_n$ and $t_1,...,t_n$ be the $\alpha$ values and $T$-count reductions
    of each of the $n$ constituent decompositions to obtain $d$ from the initial Clifford+T diagram.
    Then the efficiency $\alpha$ value of the decomposition $d$ is given by
\begin{equation}
    \label{eq:alpha-bound}
    \alpha(d) \leq \frac{\sum_{i=1}^n \alpha_i t_i}{\sum_{i=1}^n t_i}
\end{equation}
\end{lemma}

\begin{proof}
    Each decomposition gives $\leq 2^{\alpha_i t_i}$ terms, for a total of
    \[\leq \prod_{i=1}^{n} 2^{\alpha_i t_i} = 2^{\sum_{i=1}^n \alpha_i t_i}\]
    terms. Since the final $T$-count is 0, the initial $T$-count is $\sum_{i=1}^n t_i$.
    By definition, we have 
    \[\alpha \leq \frac{\sum_{i=1}^n \alpha_i t_i}{\sum_{i=1}^n t_i}\]
\end{proof}

This tells us that the final $\alpha$ value is essentially a weighted average of the $\alpha_i$ values,
weighted by their $T$-count reductions.
It is easy to see that if all decompositions have $\alpha_i \leq \alpha_{max}$,
then (\ref{eq:alpha-bound}) implies the overall $\alpha \leq \alpha_{max}$.
The actual $\alpha$ value in practice is likely to be much lower than this upper bound,
because of step 3 in Algorithm \ref{alg:stabiliser-decomposition}, 
where we simplify the diagram using \nameref{alg:zx-simplify}.
In \cite{Kissinger_2022}, although the BSS decomposition has the $\alpha \approx 0.468$,
the actual $\alpha$ value obtained in experiments was lower, at $\approx 0.4$ \cite{sutcliffe2024proccut}.

A step further than using the $\alpha$ value of a decomposition,
is to consider the $\alpha$ value when including the simplification step.
In \cite{Codsi2022}, this is defined as the \textit{effective} $\alpha_e$ value.
If the associated number of $T$-like spiders removed is $r,r_e$, where $r \leq r_e$ 
before and after simplification respectively, then we have

\begin{equation}
    \label{eq:effective-alpha}
    \alpha_e = \frac{r}{r_e} \alpha
\end{equation}

This relation can make a significant difference especially for low values of $r$.
In the next section, we also consider the structure of the diagram to increase $r_e$.

Recall also that the Algorithm \ref{alg:stabiliser-decomposition} has $O(t^2)$ part of the complexity
between each step of the decompisition.
Given that we have $k$ decompositions to choose from at each node,
if we employed a brute force approach to find the best stabiliser decomposition,
and attempted to find the best decomposition from a node traversing down $d$ levels in the tree,
it would take $O(k^{d+1} m^d t^2)$ time, where $m$ is the maximum number of terms coming from a decomposition,
for the $k$ decompositions to be applied to all the $m$ terms after each level.
For example, the above approach of obtaining $\alpha_e$ takes $d=0$.

In theory, this could be extended to larger values of $d\geq 1$, but with $km\geq 2$,
this would mean that the overall exponential complexity of $O(2^{\alpha t + d\log mk}kt^2)$ would be affected.
This motivates the idea of using heuristics instead.

\section{Cut Heuristic}
\label{sec:cut-heuristic}

A disadvantage of the greedy algorithm is that it does not take into account the structure of the diagram.
When we only consider the $\alpha$ value of the decomposition, 
we fail to take into account that $T$-like spiders can be fused in between decompositions
where decompositions with seemingly higher $\alpha$ values may actually be more efficient.

In \cite{sutcliffe2024proccut}, the heuristic used considers the structure of CNOT gates
placed in between $T$ gates.
The following observation was made.

\begin{equation}
    \tikzfig{picom_01}
\end{equation}

Using the graph \CutRule, 
which without simplification has $\alpha = 1$ if the spider being cut is a $T$-like spider,
we can instead obtain a decomposition with $\alpha \approx 0.333$, with simplication,
for the reduction of 3 $T$-like spiders at the cost of 2 terms.
In fact, this structure can be stacked in the following way.

\begin{equation}
    \tikzfig{picom_grouped}
\end{equation}

Using these observations, a heuristic weighting function can be developed,
where the main idea is to count the number of $T$-like spiders that can be removed,
divided by how many cuts are needed to remove them.

\begin{definition}
    Let $V$ be a Clifford+T diagram, and let $v$ be a vertex in $V$.
    Let $C$ be the set of sequence of graph cuts.
    For each $c=(v_c,...)\in C$ where there are $|c|=n$ cuts in the sequence,
    let $t(c)$ be the number of $T$-like spiders removed by the sequence of cuts 
    using \CutRule, including simplifications between each cut.

    The \textit{effective cut heuristic} $h_e:V\to \mathbb{R}^+$ 
    for a sequence $c$ of length $n$ is defined as
    \begin{equation}
        h_e(v_c) = \frac{t(c)}{|c|}
    \end{equation}

    A cut heuristic $h:V\to \mathbb{R}^+$ for sequences $c$ of length $n$ is \textit{valid} if
    \begin{equation}
        \forall v\in V, \exists c=(v,...,v_n)\in C, h(v) \leq h_e(v)
    \end{equation}
\end{definition}

Note that a useful cut heuristic is one where the value of $h(v)$ is close to $h_e(v)$, $\forall v\in V$.
We have that a higher cut heuristic value implies a more efficient decomposition.
In fact, the associated $\alpha_e$ value of the best sequence of \CutRule decompositions $c$ is given by 

\begin{equation}
    \label{eq:cut-heuristic}
    \alpha_e(c) = \frac{|c|}{t(c)} = \frac{1}{h_e(v_c)} \leq \frac{1}{h(v_c)} = \alpha_h(c)
\end{equation}
where $\alpha_h(c)$ is the associated $\alpha$ value of the cut heuristic,
and since the $n=\log_2(2^n)$ cuts contribute to $2^n$ terms.

If the sequence of cuts leads to a stabiliser decomposition,
the effective cut heuristic is closely related to our $\alpha_{\chi}$ value,
but does not take into account the other decompositions we have available.
For some Clifford+T diagram $V$,
let $C$ be the set of sequences of decompositions resulting in a stabiliser decompositions 
that only use graph cuts, and $D$ be the set of stabiliser decompositions. 
Let $f: C \to D$ be the function that maps a sequence of cuts to the decomposition obtained.
Let $c^*=(v^*,...)\in C$ be the most efficient decomposition using graph cuts such that
\begin{equation}
    |f(c^*)|=\min \{\left|f(c)\right| \mid c\in C\}
\end{equation}
Here, $\forall c=(v,...)\in C, h_e(v^*) \geq h_e(v)$.
If $c^*$ results in a decomposition where $|f(c^*)|=\chi(V)$,
then $\alpha_{\chi} = \alpha_e(c^*)$
\footnote{Here, and in (\ref{eq:cut-heuristic}), we overload notation 
by equating $\alpha(f(c^*)) = \alpha(c^*)$}.
In general, however, $\alpha_{\chi} \leq \alpha_e(c^*)$.
A simple example of this can be seen in the following diagram,
where the decomposition makes use of \catstate{4} (\ref{eq:cat-4-decomp}).
It starts with a $T$-count of 5.

\begin{equation}
    \tikzfig{alpha_c_more_ex}
\end{equation}
Using only cuts would require 2 of them, which would give $2^2$ terms instead of 2 terms.
We have
\begin{equation}
    \alpha_{\chi} \leq \frac{1}{5} < \alpha_e(c^*) = \frac{2}{5}
\end{equation}

\section{CNOT Sandwich Heuristic}

In \cite{sutcliffe2024proccut}, the cut heuristic used concentrated on sequences of cuts that
were looking to eliminate CNOT gates sandwiched between $T$-like spiders gates.
As a result, $71\%$ of the time, they were able to obtain $c^*$ on small circuits.
Ultimately, efficiency values of $0.1 \lesssim \alpha \lesssim 0.2$ were obtained in practice,
considering semi-structured diagrams.

Using the cut heuristic means that there is some expert knowledge on the sequences of cuts to be made.
With better consideration of sequences, we can continue to use the greedy approach
on $\alpha$ values, with the hope of obtaining a more efficient decomposition.
In the tiered approach of \cite{sutcliffe2024proccut}, a brief description is that 
increasing lengths of sequences were considered,
where each sequence of cuts $c_i$ for tier $i$ led to computation of the cut heuristic $h_{i+1}(v)$,
corresponding to sequences $c_{i+1}=k_i:c_i$ for tier $i+1$ 
for some sequence of vertices $k_i=(v,...)$.
Eventually, the algorithm terminates when there is some $l=i_{\max}$ 
where there are no sequences of vertices $k_l$ to compute $c_{l+1}$ at tier $l+1$.
The result is the computation of $h_i$ values for tiers $i\leq l$,
and the choice to cut $v$ where 
\begin{equation}
    v_{best} := \argmax_{v} h_l(v) = \argmin_{v} \alpha_{h_l}(v)
\end{equation}

\section{2-Legged Heuristic}
\label{sec:2-legged-heuristic}

The cut heuristic is also useful outside of CNOT sandwiches.
Particularly, the reduced gadget form contains structures that when cut, reduce the $T$-count greatly.

In \cite{Codsi2022}, the following observation was made when applying the cut to a \catstate{3}.

\begin{equation}
    \tikzfig{cat3-2}
\end{equation}

The associated efficiency is $\alpha = 1/3$ here, from removing 3 $T$-like spiders at the cost of 1 cut.
This means that any $T$-like spider that is part of multiple \catstate{3} can contribute to removing
all the associated $T$-like spiders at once.
A visualisation can be seen below (\ref{eq:cat-3-cut}).
It can be noted that a \catstate{3} and a two-legged phase gadget are interchangeable concepts
in the reduced gadget form.

\begin{equation}
    \label{eq:cat-3-cut}
    \tikzfig{cat-3-cut-multi}
\end{equation}

In \cite{Codsi2022}, the effective $\alpha_e$ value was used, 
after determining the number of \catstate{3} each $T$-like spider was part of,
in order to find the most suitable cut to compare with the other decompositions.
As such, there was no calculation of the heuristic $\alpha_h$ value.
We will see in \autoref{sec:random-iqp} as well, how this observation was related to the improved bounds
on the complexity of simulating IQP circuits \cite{codsi2023}.

Here, we can define the heuristic as follows.
\begin{equation}
    \label{eq:cut-heuristic-cat3}
    h(v) = 1 + 2 \cdot (\text{\# \catstate{3} $v$ is part of})
\end{equation}
since each neighbouring \catstate{3} can contribute to the removal 2 $T$-like spiders.

\begin{proposition}
    For any ZX-diagram in reduced gadget form, the heuristic $h(v)$ (\ref{eq:cut-heuristic-cat3}) 
    is a valid cut heuristic for a single cut if $v$ is $T$-like.
    \[\forall v\in V, v \text{ is T-like} \implies 0 < h(v) \leq \frac{t(c)}{|c|} = h_e(v)\]
\end{proposition}

\begin{proof}
    If $v$ is part of a phase gadget, this is trivial, as $h(v)=3$.
    Suppose $v$ has neighbours $w_1,...,w_k$ that are 0-spiders that are part of \catstate{3} states.
    Note that $w_1,...,w_k$ are all part of phase gadgets, by Definition \ref{def:reduced-gadget-form}.
    Each $w_i$ then has 2 legs, one of which is connected to $v$.
    Since no two phase gadgets have the same exact legs, we must have for all $w_i, w_j, i\neq j$,
    that their other legs do not connect to the same vertex $u$.
    By cutting only $v$, we can remove at least $2k+1$ $T$-like spiders 
    corresponding to $k$ \catstate{3} states, and vertex $v$.
    Then we must have
    \begin{equation}
        h_e(v) \geq 2k+1 = h(v)
    \end{equation}
\end{proof}
\begin{figure}[h!]
\ctikzfig{cat3_heuristic_ex}
\caption{Diagram to showcase the heuristic (\ref{eq:cut-heuristic-cat3})}
\end{figure}

We can note that even if $k$ is small, the heuristic can be quite effective.
For instance, with $k=2, \alpha_h = 0.2$ which is already an improvement over
all the \catstate{n} decompositions in \cite{Kissinger2022cat,Kissinger_2022},
the best of which is $\alpha = 0.25$ for the \catstate{4} decomposition.
A $T$-like spider simply has to be connected to 2 \catstate{3} states to improve the decomposition.

More generally, it was also considered that cutting $T$-like spiders part of \catstate{n} states
would convert them to \catstate{n-1} states.
However, this was not considered in the heuristic of \cite{Codsi2022},
as they focused on obtaining the single-step $\alpha_e$ value.

The heuristic considering \catstate{n} states could then be defined as follows.

\begin{equation}
    \label{eq:cut-heuristic-catn}
    h(v) = \sum_{i=1}^k \frac{2}{n(w_i) - 2}
\end{equation}
where $w_i$ are neighbours of $v$ that are 0-spiders that are part of $\catstate{n(w_i)}$ states,
for $n: V \to \mathbb{N}$.
The heuristic considers sequences of cuts for every $\catstate{n(w_i)}$ that $v$ is part of,
and attempts to add up each pair of $T$-like spiders that could be removed with $n(w_i) - 2$ cuts.
Unfortunately, this heuristic is not a valid heuristic in general.

\begin{figure}[h!]
\ctikzfig{invalid_heuristic_ex}
\caption{Diagram where the heuristic (\ref{eq:cut-heuristic-catn}) is not valid}
\end{figure}

Here, the heuristic would give $h(v_2) = \frac{2}{1} + 2 = 3$, 
but cutting 2 vertices to remove 5 $T$-spiders would mean $h_e(v_2) = \frac{5}{2} < 3$.

We show that with an added condition, the heuristic is valid.

\begin{proposition}
    \label{prop:cut-heuristic-catn}
    Suppose $v$ has 0-spider neighbours $w_1,...,w_k$ that are part of all $\catstate{n(w_i)}$ states.
    Let $T(w_i)$ be the set of $T$-like spiders that is part of each $\catstate{n(w_i)}$ state,
    so $|T(w_i)| = n(w_i)$.
    Let $r=\frac{\max \{n(w_i)\}_i - 2}{\min \{n(w_i)\}_i - 2}$.
    Then for the heuristic $h(v)$ (\ref{eq:cut-heuristic-catn}), we have
\begin{equation}
    \left|\bigcup_{i=1}^k T(w_i)\right| \geq 2k^2 r
    \implies \exists c=(v,...)\in C, 0 < h(v) \leq \frac{t(c)}{|c|} = h_e(v)
\end{equation}
    In other words, if the number of distinct $T$-like spiders part of all the $\catstate{n(w_i)}$ states
    is at least $2k^2 r$, then the heuristic $h(v)$ is a valid cut heuristic.
\end{proposition}

\begin{proof}    
    Note that $w_1,...,w_k$ are all part of phase gadgets, by Definition \ref{def:reduced-gadget-form}.
    By cutting at most $\sum_{i=1}^k (n(w_i) - 2)$ $T$-like spiders as legs of the phase gadgets,
    we can remove at least $\left|\bigcup_{i=1}^k T(w_i)\right|$ $T$-like spiders.
    Then we must have 
\begin{equation}
    h_e(v) \geq \frac{\left|\bigcup_{i=1}^k T(w_i)\right|}{\sum_{i=1}^k (n(w_i) - 2)} 
\end{equation}
Then
\begin{equation}
\begin{aligned}
    h(v) &= \sum_{i=1}^k \frac{2}{n(w_i) - 2} \\
    &\leq \sum_{i=1}^k \frac{2}{\min \{n(w_i)\}_i - 2} \\
    &= \frac{2kr}{\max \{n(w_i)\}_i - 2} \\
    &= \frac{2k^2 r}{k(\max \{n(w_i)\}_i - 2)} \\
    &\leq \frac{\left|\bigcup_{i=1}^k T(w_i)\right|}{\sum_{i=1}^k (n(w_i) - 2)} \\
    &\leq h_e(v)
\end{aligned}
\end{equation}
\end{proof}

The proposition condition is generally unlikely to be satisfied,
and ultimately leads to the heuristic performing poorly in general.
From the proof, we can gather that there is in fact a cut heuristic that is valid.

\begin{corollary}
    The following heuristic is a valid cut heuristic.
\begin{equation}
    \label{eq:cut-heuristic-catn2}
    h(v) = \frac{\left|\bigcup_{i=1}^k T(w_i)\right|}{\sum_{i=1}^k (n(w_i) - 2)} \leq h_e(v)
\end{equation}
\end{corollary}

Unfortunately, although the heuristic is valid, it can vastly underestimate the effective heuristic value. 
This happens when there is a large overlap in $T$-like spiders connected to different phase gadgets.
A simple example is as follows, where we have $\catstate{n}$ for $n=3,4,5$.

\begin{figure}[h!]
\ctikzfig{overlap_legs}
\caption{Diagram where the heuristic (\ref{eq:cut-heuristic-catn2}) 
underestimates the effective heuristic value}
\end{figure}

$h_e(v_1) \geq \frac{7}{3}$ since only 3 cuts are needed to remove 7 $T$-spiders,
but $h(v_1) = \frac{4}{3+2+1} = \frac{2}{3} < \frac{7}{3}$.

\section{Lone Phase Heuristic}
\label{sec:lone-phase-heuristic}

Another heuristic turns out to be somewhat common to measure is the lone phase heuristic.
We can observe the following decomposition.

\begin{equation}
    \tikzfig{lone_phase}
\end{equation}

Since the legless spiders can easily be treated as scalars,
a $T$-like spider connected to $n$ magic states $\cbox{\magicspider}$ would allow the $T$-count to drop by $n$.
We define the \textit{lone phase heuristic} as follows.

\begin{equation}
    \label{eq:lone-phase-heuristic}
    h(v) = 1 + \# \cbox{\magicspider} v \text{ is connected to}
\end{equation}
It's clear to see that this is a valid cut heuristic.

What we have then is that we can combine the two "simple" heuristics 
(\ref{eq:cut-heuristic-cat3}, \ref{eq:lone-phase-heuristic}) so far.
If $n$ is the number of \catstate{3} states $v$ is part of, 
and $m$ is the number of magic states $\cbox{\magicspider} v$ is connected to,
then we have the following heuristic.

\begin{equation}
    \label{eq:cut-heuristic-combined}
    h(v) = 1 + 2n + m
\end{equation}

There is clearly no overlap between the two types of $T$-like spiders that each heuristic considers,
so the heuristic is still valid.
Surprisingly, just a simple combination of the two heuristics can be quite effective in practice,
as we will see in the next chapter.

\section{Paired Heuristics}
\label{sec:paired-heuristics}

The heuristics thus far concentrate on cutting single vertices, 
with the hope of further simplification aftewards.
However, we can also consider heuristics that involve cutting pairs of vertices.
Consider the following diagram.

\begin{figure}[h!]
    \ctikzfig{pair_ex}
    \caption{A pair of vertices connected to 3-legged phase gadgets}
\end{figure}

We see at the top that we have $n$ 3-legged phase gadgets (a.k.a. \catstate{4} states),
fully connected to a pair of $T$-like spiders.
At first glance, it might seem like gadget fusion \GFRule can almost be applied,
and that we need to remove the $n$ $T$-like spiders at the top to do so.
However, this is not too optimal, since we at most remove $2n$ $T$-like spiders
with $n$ cuts, giving an $\alpha = 0.5$.
Instead, we can exploit the fully connected aspect of the pair of $T$-like spiders,
by considering the $\PivotRule$ivot rule again.

\begin{equation}
    \tikzfig{pair_eq}
\end{equation}

Then we can \CutRule vertex $v$ to remove the $T$-like spiders.

\begin{equation}
    \tikzfig{pair_eq_cut}
\end{equation}

A total of $2n+2$ $T$-like spiders are removed with a single cut, giving an $\alpha = \frac{1}{2n+2}$.

We can go even further, if we draw inspiration from the \nameref{sec:lone-phase-heuristic}.
If we have a pair of $T$-like spiders fully connected to $m$ 2-legged $T$-like spiders,
we can again use the $\PivotRule$ivot rule to our advantage.

\begin{equation}
    \tikzfig{pair_eq_phase}
\end{equation}

We can summarise the paired heuristic as follows.
Suppose $t_1,t_2$ are $T$-like spiders fully connected to $n$ 3-legged phase gadgets,
and $m$ 2-legged $T$-like spiders respectively.
Let $v$ be the vertex added after using the $\PivotRule$ivot rule.
Then we have two heuristics.

\begin{equation}
\begin{aligned}
    \label{eq:cut-heuristic-pair}
    h_1(t_1,t_2) &:= h_1(v) = 2 + 2n \\
    h_2(t_1,t_2) &:= h_2(v) =  2 + m
\end{aligned}
\end{equation}

In this case, we don't necessarily merge the two heuristics since the pivot vertices are different.
We could consider a combined heuristic, where the 2 pivots happen at the same time,
so 2 cuts are needed to remove all the vertices.

\begin{equation}
\begin{aligned}
    h(v) &= \frac{2 + 2n + m}{2} \\
    &< \frac{h_1(v) + h_2(v)}{2} \\
    &\leq \max\{h_1(v), h_2(v)\}
\end{aligned}
\end{equation}

This is essentially the average of the two heuristics, 
which is necessarily smaller than the maximum between the two heuristics.
Since we can process the heuristics sequentially, we can just consider them separately as before.
By doing so, we maintain the validity of the heuristics with the same argument as before 
(\ref{eq:cut-heuristic-combined}).

\section{$k$-connected Heuristics}
\label{sec:k-connected-heuristics}

We can extend the idea of paired heuristics to $k$-connected heuristics.
Suppose we have $k$ $T$-like spiders $\vec{t}_k = (t_1,...,t_k)$ fully connected to $n$ $k+1$-legged phase gadgets,
and $m$ $k$-legged $T$-like spiders.
Using the $\PivotRule$ivot rule, we can remove $m$ or $n$ $T$-like spiders with a single cut as before.

\begin{equation}
    \tikzfig{k-connected}
\end{equation}

Then we have the following valid heuristics.

\begin{equation}
\begin{aligned}
    \label{eq:cut-heuristic-k}
    h_1(\vec{t}_k) &= 2n \\
    h_2(\vec{t}_k) &= m
\end{aligned}
\end{equation}

The drawback of this heuristic is that it can be relatively expensive to compute.
We will see in the next \autoref{sec:complexity} that the complexity of computing the heuristic 
is $O(kt^{k+1})$ given a $T$-count $t$.
This results in an overall time complexity of $O(2^{\alpha t}t^{k+1})$,
which practically affects runtime heavily for low $t$, even if $\alpha$ is reduced significantly.
As such, we leave this general heuristic to be useful in much larger computations,
and in numerical experiments of \autoref{ch:4-results}, we only consider the case of $k=1,2$,
corresponding to (\ref{eq:cut-heuristic-combined}, \ref{eq:cut-heuristic-pair}).

\section{Greedy Algorithm with Cut Heuristic}
\label{sec:greedy-cut}

A natural extension of the greedy algorithm is to also consider 
the cut heuristic on top of the cat decompositions.

We have the $\alpha$ values from decompositions of \catstate{4}, \catstate{6}, \catstate{5}, \catstate{3},
and magic state $\cbox{\magicspider}^{\otimes 5}$
being $0.25 < 0.264 < 0.317 < 0.333 < 0.396$ respectively.
Depending on the value of the best heuristic (\ref{eq:cut-heuristic-combined}), $\max_v h(v)$,
and the best available \catstate{n} decomposition in the diagram,
we can continue to use the greedy approach.
We have the simple Algorithm \ref{alg:greedy-cut}.

\begin{algorithm}
\caption{Greedy Algorithm with Heuristic}
\label{alg:greedy-cut}
\begin{algorithmic}[1]
\State \textbf{Input:} $\alpha$ values for $\catstate{4}$, $\catstate{6}$, $\catstate{5}$, $\catstate{3}$, 
and $\cbox{\magicspider}^{\otimes 5}$, and the graph $G$
\State \textbf{Output:} Chosen state and corresponding decomposition

\State Let $\alpha_{4} = 0.25, \alpha_{6} = 0.264,\alpha_{5} = 0.317, \alpha_{3} = 0.333, 
\alpha_{\otimes 5} = 0.396$
\State Compute the best catstate $\catstate{best}$ in $G$ with the lowest $\alpha$ value
\State Let $\alpha_{best}$ be the $\alpha$ value of $\catstate{best}$, 
or of $\cbox{\magicspider}^{\otimes 5}$ if no $\catstate{best}$ is found

\State Compute $\alpha_h$ on $G$ using a heuristic

\If {$\alpha_h < \alpha_{best}$}
    \State Use the decomposition corresponding to the heuristic
\Else
    \State Use the decomposition corresponding to $\catstate{best}$ or $\cbox{\magicspider}^{\otimes 5}$
\EndIf

\end{algorithmic}
\end{algorithm}

Even with a small values of $n,m$, the heuristic can be quite effective.
Just having $n=m=1$ can already give a $\alpha_h = 0.25$, matching the best \catstate{4} decomposition.
Furthermore, this will cut the graph at a vertex, as compared to the \catstate{4} decomposition,
which only locally partitions the second of its 2 terms, 
while its first term remains connected, seen below.

\end{equation}

This heuristic also works in a diagram without any phase gadgets where $n=0$, concentrating on the $T$-like spiders.
In this scenario, having $m=2$ will already give a better $\alpha_h=1/3$ 
than the default \hyperref[eq:magic-5-decomp]{5-qubit magic decomposition} at $\alpha \approx 0.396$.

\section{Other Heuristics}
\label{sec:other-heuristics}
Another heuristic considered, based off (\ref{eq:cut-heuristic-catn2}) 
takes into account the overlap of $T$-like spiders,
and not overcount the number of cuts needed.
Suppose the $T$-spider part of each phase gadget $w_i$ is labelled vertex $g_i$.
Each phase gadget as part of a $\catstate{n}$ would only need a maximum of $n-2$ cuts,
so our heuristic would look like

\begin{equation}
    \frac{\left|\bigcup_{i=1}^k T(w_i)\right|}
    {1+\left|\bigcup_{i=1}^k T(w_i) - \{g_i, v, u_i\}\right|}
\end{equation}
where $\forall i, u_i \in T(w_i)$ is a chosen $T$-like spider on the leg of phase gadget $w_i$,
that does not need to be cut.
We would want to choose the $u_i$ that minimizes the denominator, so we have the following heuristic.

\begin{equation}
    \label{eq:cut-heuristic-catn-max}
    h(v) = \max_{\forall i, u_i\in T(w_i)} h(v)
\end{equation}
where the denominator is minimized.
\begin{equation}
    t_{\min} = 1+\min_{\forall i, u_i\in T(w_i)} \left|\bigcup_{i=1}^k T(w_i) - \{g_i, v, u_i\}\right|
\end{equation}

It is easy to see that this heuristic is valid, 
by the same argument as the previous Proposition \ref{prop:cut-heuristic-catn}.
Solving this is akin to maximum bipartite matching.
This is because to minimize the number of cuts, the number of $T$-like spiders matched with a phase gadget
needs to be maximized, while only one $T$-like spider can be matched with each phase gadget.
The matching can be found in polynomial time using any maximum bipartite matching algorithm 
like the Hopcroft-Karp algorithm \cite{Hopcroft1973}.
Unfortunately, this heuristic is not as effective as the previous heuristic (\ref{eq:cut-heuristic-cat3})
just involving \catstate{3} states.

The phase gadget heuristic is also considered, where the $T$-like spiders connected to the legs 
of two phase gadgets $w_i,w_j$ are compared.
Let $T(w_i),T(w_j)$ be the $T$-like spiders connected to the legs of $w_i,w_j$ respectively.
Recall from \GFRule, that gadgets with the same set of legs can be fused.
If all the $T$-like spiders from the symmetric difference $T(w_i) \Delta T(w_j) $ are removed, where
\begin{equation}
    A \Delta B = (A \cup B) - (A \cap B)
\end{equation}
then the $T$-count can be reduced by 2 via gadget fusion \GFRule, as seen below.

\begin{equation}
    \label{eq:phasegadget_heuristic_ex}
    \tikzfig{phasegadget_heuristic_ex}
\end{equation}

We could then have the following heuristic, for the simplest case where 
\[\exists i,j, T(w_i) \Delta T(w_j) = \{g_i,g_j,v\}\]
\begin{equation}
    h(v) = 1 + 2\cdot \left|\{\{w_i,w_j\} \mid T(w_i) \Delta T(w_j) = \{g_i,g_j,v\}\}\right|
\end{equation}
where $g_i,g_j$ are the $T$-like spiders part of the phase gadgets $w_i,w_j$ respectively.

This heuristic is valid, due to the requirement that $\{w_i,w_j\}$ must be distinct.
As such, there is no overcounting of the number of $T$-like spiders that can be removed.

Similarly, the paired version of the heuristic can be considered,
where there are 2 extra $T$-like spiders preventing gadget fusion.

\begin{equation}
    \tikzfig{pg_pair}
\end{equation}


Alas, these phase gadget heuristics are not effective in practice,
and earn their place in the "other heuristics" category.
Scenarios for being close to gadget fusion are not common enough, and tend to take more cuts than necessary,
by which time the cut heuristics (\ref{eq:cut-heuristic-combined}, \ref{eq:cut-heuristic-pair}) 
would have already been more effective.

In \autoref{sec:subgraph-complement}, we introduce the subgraph complement cut.
The heuristic that could be used here is simply to determine the number of edges 
in the subgraph excluding the phase gadgets,
and to carry out the cut if the number of edges was above a certain threshold.
For example, with $k$ vertices in the subgraph, we could cut if there were 
$>p\cdot\frac{k(k-1)}{2}$ edges for some $0.5 < p \leq 1$.
We only tested with $p=3/4$ and chose the subgraph of vertices not part of the phase gadgets, 
which did not seem to affect the results much.

Smartly choosing the right subgraph that are near cliques to execute the cut would be useful here,
as demonstrated in \autoref{sec:subgraph-complement},
but finding near cliques is at least as hard as the maximum cliques problem, 
which itself is NP-hard \cite{behera2022}.
However, there is work done on partitioning graphs that will be considered 
in future work \cite{sutcliffe2024part}.

\section{Complexity Analysis}
\label{sec:complexity}

Here, we consider the complexity of computing the heuristics.

Suppose we have a reduced gadget form $V$ with $n$ phase gadgets 
and $m$ $T$-like spiders not part of phase gadgets.
Let $d(v)$ be the degree of a vertex $v$.

\begin{figure}[h!]
\[\overbrace{\underbrace{\tikzfig{complexity-ex}}_m}^n\]
\caption{ZX-diagram in reduced gadget form, with $n$ phase gadgets and 
$m$ non-phase gadget $T$-like spiders}
\end{figure}

For the heuristic (\ref{eq:cut-heuristic-cat3}), it is easy to compute the heuristic in $O(mn)$ time.
Checking which 0-spiders are part of \catstate{3} states can be done in $O(n)$.
Each $T$-like spider $v$ can be processed in $O(d(v)) = O(n)$ time,
and checking for all of them takes $O(mn)$, for an overall of $O(n + mn) = O(mn)$ time.

The heuristic (\ref{eq:cut-heuristic-catn}) has a similar complexity of $O(mn)$.

For the \catstate{n} heuristic (\ref{eq:cut-heuristic-catn2}), a single $T$-like vertex $v$,
and its 0-spider neighbours $w_1,...,w_k$,
it takes 
\begin{equation}
    O\left(d(v) + \sum_{i=1}^k d(w_i)\right) = O(n+mn) = O(mn)
\end{equation}
time to compute the heuristic.
For all $m$ $T$-like spiders, this takes $O(m^2 n)$ time.

The lone phase heuristic (\ref{eq:lone-phase-heuristic}) can be computed in $O(m^2)$ time,
since each $T$-like spider can be processed in $O(m)$ time, for all $m$ $T$-like spiders.

Combining the complexities for the general heuristic (\ref{eq:cut-heuristic-combined}) 
will take $O(mn + m^2)$ time.
With the existing greedy algorithm from \cite{Kissinger2022cat,Kissinger_2022} 
that has complexity $O(2^{\alpha t}t^2)$, and since $m+n=t$, 
the complexity remains unchanged.
Specifically, looking at the $O(t^2)$ operations in between decompositions,
\begin{equation}
    O(t^2 + mn + m^2) = O(t^2)
\end{equation}

Comparing to the method of \cite{Codsi2022} which 
requires computing $\alpha_e$ values (\ref{eq:effective-alpha})
for each of the $p$ decompositions considered to select the best one, 
the number of operations between each decomposition there is $O(pt^2)$.

The paired heuristics are (\ref{eq:cut-heuristic-pair}) are slightly more costly than 
the single heuristics, with a complexity of $O(m^2(n+m))$.
Each pair of $T$-like spiders can have at most $O(n)$ phase gadget neighbours,
and $O(m)$ $T$-like spider neighbours, and so can be processed in $O(n+m)$ time.
With the $O(m^2)$ pairs of $T$-like spiders, the complexity is $O(m^2(n+m))$.
This overhead cost comes into play since $O(m^2(n+m)) = O(t^3)$ in the worst case,
compared to the original $O(t^2)$ complexity. 
With a higher $T$-count, and the reduction of $\alpha$ due to more efficient cuts,
we will see that the paired heuristics can still be effective in practice.

However, in better cases, where $m \ll n \leq t$, we can have $O(t)$ complexity instead.
Such cases can be described in the next chapter in \autoref{sec:experiments} 
when we see different classes of circuits being affected differently by the overhead cost.

The $k$-connected heuristics (\ref{eq:cut-heuristic-k}) considers $O(m^k)$ $k$-connected $T$-like spiders,
requiring the check of $O(k(m+n))$ edges, for a total of $O(m^k(m+n)k)$ time.
In the worst case, this is $O(kt^{k+1})$, showing its impracticality for small $t$.

For the heuristic taking into account the overlap of $T$-like spiders (\ref{eq:cut-heuristic-catn-max}),
the Hopcroft-Karp algorithm has a complexity of $O(mn\sqrt{m+n})$ for each $T$-like spider,
for a total of $O(m^2 n\sqrt{m+n})$ time.

For the phase gadget heuristic (\ref{eq:phasegadget_heuristic_ex}), to compare two phase gadgets is $O(m)$,
for a total of $O(mn)$ for all phase gadgets.
Computation for all $m$ $T$-like spiders can be done at the same time, so the complexity is $O(mn)$.

The simple subgraph complement heuristic can be computed in $O(m^2)$ time.
